# Release Notes

Use when command intent matches `/release-notes` or "changelog for this release."

## Workflow

1. **Audience**: End users, internal ops, or both (human specifies).
2. **Version or date**: Human provides or COGO proposes from tags/commits.
3. **Highlights**: 3–7 bullets of user-visible or operator-visible changes.
4. **Breaking changes**: Explicit section with migration steps.
5. **Known issues**: Short list if any.
6. **Rollout**: Feature flags, migrations, or ordering if deploy-sensitive.

Tone: clear and factual; avoid internal jargon unless the audience is internal only.
